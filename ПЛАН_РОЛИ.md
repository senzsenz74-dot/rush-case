# План: роли в админке (Владелец / Сотрудник)

Решено с владельцем 30.10.2026. Делать по этапам; после каждого этапа сайт работает.
Правило проекта: SQL на прод — вставляем в Supabase SQL Editor, Run нажимает владелец; секреты в чат не присылать;
после каждой выкладки — версия `?v=` в index.html, запись в ЖУРНАЛ.md, коммит, push (= выкладка на Beget).

## Роли
- **Владелец** — всё. Сейчас владелец — аккаунт пользователя (все текущие админы → сотрудники, кроме владельца).
- **Сотрудник (админ)** — видит только вкладки, отмеченные владельцем. Обрабатывает обращения клиентов, редактирует витрину
  (через подтверждение владельца), подтверждает выводы скинов дороже порога (статус `wait`), видит онлайн, сдаёт отчёт смены.
  НЕ может: шансы/удачу кейсов, удачу игроков, начисления (admin_grant), финансы (Касса, деньги на дашборде, чистая прибыль),
  промокоды, настройки маркета, сотрудников.

## Безопасность — главное
Права проверяет СЕРВЕР, не только интерфейс. Сейчас все admin_* функции проверяют `public.is_admin()`.
- Добавить `profiles.role text` ('owner' | 'staff' | null) и `profiles.perms text[]` (ключи вкладок) — или таблицу `staff`.
- `is_owner()`; `has_perm(text)` (owner → true).
- Владельческие функции (только `is_owner()`): admin_grant, admin_set_luck, настройки кейсов (удача/закрыт), admin_sync,
  сохранение кастомных кейсов/шансов, admin_market_cfg, admin_promo_*, admin_support_stats (общая), касса/деньги
  (admin_period — деньги; admin_upg/bets/cases_period), выгрузка Excel, вкладка «Сотрудники».
- Сотруднику по perms: поддержка (admin_support_*), выводы (admin_wd — только approve/back/done для `wait`), онлайн
  (отдельная функция без денег), витрина (только заявки на изменение).
- RLS: таблицы с политиками `is_admin()` (withdrawals, market_cfg, support_*, promo_codes, profiles: admin read) — пересмотреть:
  сотруднику не видеть балансы/финансы игроков сверх нужного (для поддержки — ID, ник, баланс игрока можно).

## Этап 1 — роли и вкладка «Сотрудники»
- Вкладка «Сотрудники» (только владелец): выдать права по ID игрока, галочки вкладок, график смен (дни недели + часы), снять права.
- Админка показывает только разрешённые вкладки; сервер отказывает в остальном.

## Этап 2 — витрина через подтверждение владельца
- Изменения сотрудника в «Управлении витриной» → заявка (таблица showcase_requests: кто, что, diff, статус).
- Бот (функция support-bot или отдельная) шлёт в чат владельцев «… хочет изменить … ✅ Одобрить / ❌ Отклонить» (inline-кнопки,
  callback_query уже обрабатывается в support-bot). Одобрено → применяется (site_cfg / custom_cases), отклонено → сотруднику статус.
- Нужен chat_id чата владельцев (бот добавлен в группу) — хранить в настройке (не секрет).

## Этап 3 — отчёт смены
- Смена = по графику сотрудника (задаёт владелец). Кнопка «Сдать отчёт» в конце смены.
- Бот отправляет в чат владельцев текст: обращений закрыто, средняя оценка, выводов подтверждено (шт, ₽), онлайн и пик за смену,
  заявки на витрину, комментарий сотрудника.

## Где что лежит
- Админка: js/app.js — ADM_TABS, admDraw, ax* (вкладки), admSupport, axOut, admPromo, admCases (витрина).
- SQL: supabase/*.sql (admin.sql, admin2.sql, admin3.sql, no_admins.sql, support*.sql, market.sql, promo_admin.sql…).
- Бот: supabase/functions/support-bot/index.ts (TG_BOT_TOKEN в секретах, вебхук — кнопка «Переподключить» в админке).
