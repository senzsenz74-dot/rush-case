## 2. Какую кассу выбирать

**Важно:** кейс-сайты для платёжных систем — «высокий риск» (близко к азартным играм).
Обычные эквайеры — **ЮKassa, CloudPayments, Т-Касса, Робокасса, Prodamus** — такую тематику запрещают.
Подключение без раскрытия тематики → блокировка магазина и заморозка денег. Туда подавать только честно (скорее всего откажут).

**Рассматривать:** платёжные агрегаторы, которые сами работают с играми / high-risk (СБП + карты РФ, кошельки).
Комиссия у них обычно 4–10%, бывают задержки первых выплат.

Что известно из открытых источников (быстро устаревает — проверять свежие отзывы):
- **FreeKassa** — в отзывах 2026 года много жалоб на блокировки и выводы ([crmindex](https://crmindex.ru/services/free_kassa)).
- **Lava** — «массовая серая касса», жёсткий антифрод, холд 50 тыс. для новых магазинов ([host.pink](https://host.pink/platezhki/)).
- **Antilopay, Aaio и подобные** — данных нет, узнавать напрямую.

### Как действовать
1. Отправить заявки в 3–4 агрегатора, **тематику указывать честно**: «кейсы CS2, скины».
2. Каждому задать вопросы:
   - комиссия: СБП / карты РФ / карты СНГ;
   - холд (задержка) первых выплат и на сколько;
   - работает ли касса с физическими лицами (самозанятыми) и сроки вывода на карту / счёт;
   - лимиты на платёж и в сутки;
   - принимают ли карты Казахстана, Беларуси, Узбекистана и др.;
   - есть ли вебхук (уведомление об оплате) с подписью и **тестовый режим**;
   - что требуется на сайте для проверки.
3. Подключить **двух**: основную и запасную кассу. Крупные суммы на кассе долго не держать.
4. По желанию — криптокасса (Cryptomus, NOWPayments, CryptoCloud) как дополнительный способ для СНГ.
5. Позже — пополнение скинами (вместе с выводом через Lis-Skins).
6. До запуска — консультация юриста (тематика, договор, документы).

## 4. Что уже сделано технически (основа под любую кассу)

### Как работает оплата
```
Игрок: «Пополнить» → выбирает СБП или карту, сумму, промокод → «Оплатить»
  → функция payment (create) создаёт счёт в таблице payments и получает ссылку у кассы
  → игрок платит на странице кассы
  → касса шлёт уведомление на payment (webhook)
  → функция проверяет подпись → pay_credit зачисляет баланс (+ бонус промокода, R-COIN)
  → игрок возвращается на сайт (?pay=ok) — «Оплата прошла», баланс обновляется сам
```

### Файлы
| Файл | Что это |
|---|---|
| `supabase/payments.sql` | Таблица `payments` (счета), функции `pay_credit` (зачисление) и `pay_fail` |
| `supabase/functions/payment/index.ts` | Серверная функция: создание платежа и приём уведомлений кассы; адаптеры касс |
| `js/app.js` → `PAY_LIVE`, `openDepositLive`, `payStart` | Окно оплаты на сайте (сейчас выключено, `PAY_LIVE = false`) |

### Защита
- Зачислить баланс может **только сервер** (серверная роль) — игрок напрямую не может ни зачислить, ни создать платёж.
- Повторное уведомление кассы **не зачисляет дважды**.
- Если сумма в уведомлении не совпадает со счётом — отклоняется.
- Подпись уведомления проверяется; неверная подпись → отказ.
- Проверено на копии базы: зачисление с RUSH35 (+35%), повтор, неверная сумма, попытки игрока.

### Сейчас
- Пополнение идёт **через поддержку** (игрок отправляет заявку, баланс начисляет админ в админ-панели).
- Тестовое пополнение на сервере выключено (`supabase/deposit_off.sql`).
- `payments.sql` и функция `payment` **на сервер ещё не выложены** — после выбора кассы.

## 5. Подключение выбранной кассы (чеклист)

**От владельца:**
1. Договор с кассой, магазин одобрен.
2. Прислать: название кассы и ссылку на её документацию для разработчиков (API).
3. **Ключи в чат не присылать.** Вписать их в Supabase → Edge Functions → Secrets:
   - `PAY_PROVIDER` — имя адаптера (скажу какое)
   - `PAY_SHOP_ID` — ID магазина
   - `PAY_SECRET` — секретный ключ
   - `PAY_SECRET2` — второй ключ (если касса даёт отдельный для уведомлений)
   - `PAY_API_URL` — адрес API кассы (если нужен)
4. В личном кабинете кассы указать:
   - адрес уведомлений: `https://gkeexoyrxnsarosymdyp.supabase.co/functions/v1/payment?action=webhook`
   - страница успеха: `https://rush-case.online/?pay=ok`
   - страница ошибки: `https://rush-case.online/?pay=fail`

**Разработка (~полдня):**
1. Дописать адаптер кассы в `PROVIDERS` (создание платежа + разбор уведомления с подписью).
2. Запустить `supabase/payments.sql` в SQL Editor.
3. Выложить функцию `payment`, **выключить проверку JWT** у неё (уведомления кассы приходят без токена).
4. Тестовый платёж в тестовом режиме кассы → проверить зачисление, повтор, отмену.
5. Один реальный платёж на 100 ₽.
6. Включить окно оплаты: `PAY_LIVE = true` в `js/app.js`, выложить сайт.
7. Обновить пункт «Оплата и возврат», если у кассы особые условия.

**После запуска:**
- В админке следить за платежами (`payments`, статусы `pending / paid / failed`).
- Спорный платёж: найти по номеру у кассы (`ext_id`), в поле `raw` — последнее уведомление кассы.
- Держать запасную кассу: переключение — смена `PAY_PROVIDER` и секретов.
